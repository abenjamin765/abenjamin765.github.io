# Tools are metadata unless they explain the work

**Claim:** The report says tools support a case only when they explain capability or constraints.

**Sources:** Winning-portfolios report (attachment `deep-research-report__10_.md`).

## Evidence

**Observed examples:** Joan names Figma, Maze, PiwikPro, and Relume in a validation context. Michelle lists Figma and the implementation and OCR stack because design engineering is part of the claim “I ship the front-end.” Manolo lists Adobe XD, Sketch, Optimal Workshop, and WordPress while describing lead UX plus development.

**Observed counterexamples in the report’s telling:** Eemon’s strongest case is not a “Tools: Figma, Jira” strip. Dharmesh emphasizes responsibility. Niklas emphasizes direction and organizational leverage.

## Implication for this portfolio

A tool belongs in a work story when the reader needs it to understand the constraint or the craft. It does not belong in Intro. See `../what-not-to-copy/tool-list-and-skill-marquee.md`.

## Limit

The report does not publish a count of sites with a tools strip. The judgment “much less central than beginner portfolio discourse” is the author’s.
