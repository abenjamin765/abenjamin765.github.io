# A card is for an object, not for every row

**Claim:** The report says to use a card only when the contents behave as an independent object or group, and to prefer type and spacing before containers.

**Sources:** Metro × Apple design-system report (attachment `deep-research-report__11_.md`).

## Evidence

**Prescribed:** A project summary may be a card. Every settings row should not become its own card. “Card everything” is listed as an anti-pattern because it adds chrome and weakens hierarchy.

## Disagreement

The homepage notes’ work unit is a row: company and year, a short name, and one sentence (`../work-rows-and-case-framing/work-row-unit.md`). They do not call that unit a card. This report allows a project summary to be a card and also warns against cards as default chrome. A quiet row satisfies the portfolio notes without satisfying a card layout, and a card layout is not required to satisfy this report.

## Implication for this portfolio

The Work panel can stay a scannable row. Adding a card chrome around each project is not what either source requires.

## Limit

“May be a card” is permission, not a frequency from the Wall sample.
