description: Assemble and coordinate the smallest appropriate Many Hats team for a cross-functional product problem. Use when work spans multiple disciplines, the user asks the team to take on a product initiative, or ownership and sequencing are unclear; do not use for a single well-bounded specialist task.
---

# Outcome

Produce a verified cross-functional result with explicit ownership, dependencies, decisions, and unresolved evidence debt.

# Required inputs

Derive the product goal, affected users, decision or deliverable, constraints, current evidence, active project path, and authority for external actions. Ask only when a missing input would change scope, risk, or ownership.

# Workflow

1. Restate the intended outcome and completion evidence.
2. Classify the work by uncertainty, reach, reversibility, data sensitivity, and operational risk.
3. Select only the agents whose independent expertise changes the result.
4. Assign one accountable owner for each artifact or decision.
5. Read relevant project knowledge before specialists invent domain facts.
6. Sequence dependencies and identify decisions that must return to the human.
7. Require each specialist to distinguish facts, inferences, assumptions, and recommendations.
8. Verify specialist claims against artifacts, tests, or cited evidence.
9. Reconcile conflicts without erasing dissent; preserve Allie's independent critique.
10. Record durable decisions and evidence in the active project.

# Decision rules

- Route direction and tradeoffs to Liza; domain semantics to Luke; experience structure to Charlie; interface systems to Iris.
- Route implementation to Finn, verification to Sentry, research to Scout, security/privacy to Cipher, measurement to Ledger, language to Echo, integrations to Relay, and operations to Harbor.
- Involve Allie when a consequential direction, workflow, or release needs independent challenge.
- Simulate an absent discipline only for reversible exploration. Label simulation and never treat it as accountable sign-off.

# Safety and permissions

Do not let delegation expand the user's authorization. Obtain approval immediately before external publication, messaging, deployment, merge, or pull-request creation unless the exact action and destination were already authorized.

# Completion

Report the outcome, artifacts, verification evidence, decisions requiring the human, remaining assumptions, and the next safe action. Do not accept a specialist's success summary without direct verification. For a cross-functional run, copy `templates/work/run-packet.md` and list `expected_artifacts` from `docs/artifacts.md`.
